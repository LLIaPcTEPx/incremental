# Incremental — TAS for Minecraft 1.21.11

Трейсер / Tool Assisted Speedrun мод: записывает каждое нажатие и координаты игрока по тикам,
воспроизводит запись тик-в-тик (с телепортом в записанные точки), даёт покадровую перемотку с
заморозкой мира и настраиваемую скорость записи.

Работает **только в одиночной игре** (нужен встроенный сервер, чтобы управлять тиками).

## Установка

1. Minecraft **1.21.11** + [Fabric Loader](https://fabricmc.net/use/) ≥ 0.20.1.
2. Положите [Fabric API](https://modrinth.com/mod/fabric-api) и `incremental.jar` в папку `mods`.
3. Готовый jar: [`dist/incremental.jar`](dist/incremental.jar) (собирается CI на каждый пуш),
   либо вкладка **Releases → Latest build**.

## Меню паузы

В меню паузы появляются две кнопки:

| Кнопка | Что внутри |
|---|---|
| **Настройка мода** | все клавиши мода с видимой текущей клавишей и возможностью переназначить, скорость записи, камера, оверлей, заморозка |
| **Выбор записи** | список всех записей; в самом верху всегда строка **«+ Создать»** → диалог ввода названия |

Созданные записи лежат в `.minecraft/incremental/recordings/<название>.json`, настройки — в
`.minecraft/incremental/config.json`.

## Клавиши по умолчанию

| Действие | Клавиша | Что делает |
|---|---|---|
| Начать запись | `Ins` | старт новой записи в выбранную запись, начиная с текущего кадра и текущего места |
| Остановка записи | `End` | прекращает запись (запись сохраняется) |
| Пауза записи | `C` | пауза/продолжение записи, а во время воспроизведения — пауза/продолжение проигрывания |
| Увеличение скорости записи | `.` | следующий шаг скорости (1 … 400 тиков/с) |
| Уменьшение скорости записи | `,` | предыдущий шаг скорости |
| Назад | `R` | −20 кадров (≈1 секунда) |
| Вперёд | `T` | +20 кадров |
| Назад на 1 кадр | `F` | −1 кадр (игрок ставится в координаты кадра) |
| Вперёд на 1 кадр | `G` | +1 кадр; на паузе воспроизведения — реальный прогон одного тика |
| Новый кадр | `V` | вставляет пустой кадр в позицию курсора |
| Сохранение | `[` | пишет выбранную запись на диск |
| Воспроизведение | `]` | старт/стоп воспроизведения выбранной записи |

Все клавиши переназначаются в «Настройке мода» (клик по строке → нажать новую клавишу; `Esc` —
отмена). Конфликт с другим действием TAS подсвечивается красным.

## Как это работает

* **Запись** снимает состояние в конце тика игрока — ровно то, что увидела игра: WASD/прыжок/
  присед/спринт, кнопки мыши, слот хотбара, абсолютный поворот камеры **и координаты игрока**
  вместе с измерением. Поэтому запись привязана к месту, где начался забег.
* **Воспроизведение** подменяет обработчик ввода игрока на записанный кадр до того, как ванильный
  клиент прочитает управление, поэтому клики атаки/использования попадают в тот же тик. Физика
  остаётся ванильной: движение, прыжки, воду, лаву и т.п. считает сам Minecraft. В начале каждого
  кадра игрок телепортируется в записанные координаты через серверный `teleport`, так что клиент
  и сервер не расходятся.
* **Покадрово**: `C` замораживает мир (как `/tick freeze`), `G` прогоняет ровно один тик с
  записанным кадром. `F`/`R`/`T` ставят игрока в координаты выбранного кадра — блоки и сущности
  назад не откатываются, но игрок оказывается там, где проходил забег.
* **Перемотка во время записи** ставит запись на паузу и замораживает мир; запись продолжается,
  когда курсор доходит обратно до места остановки (или по `Ins`). Кадры после курсора
  **сохраняются**: новая запись перезаписывает их поверх, а не стирает весь хвост.
* **Скорость** — это скорость **записи** (и воспроизведения) через tick rate встроенного сервера;
  на 5x запись идёт в пять раз быстрее, клиент тикает с той же частотой, чтобы игрок не «резинковал».

## Сборка

```bash
./gradlew build            # нужен JDK 25 (Loom 1.19)
```

CI на каждый пуш собирает jar и складывает его в `dist/incremental.jar`, лог — в `ci-build-log.txt`.
